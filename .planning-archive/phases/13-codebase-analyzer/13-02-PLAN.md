**ts-parser.ts** — Uses the TypeScript Compiler API (already available as devDependency; accessible at runtime in Electron main process via externalizeDepsPlugin):

```typescript

import type { CodeEntity, CallEdge, RouteInfo } from '../../renderer/src/types/codebase-analyzer'
// Note: Import from the shared types. In the main process build, electron-vite resolves these paths.
// If path resolution is an issue, duplicate the type interfaces in a local common-types.ts.

export interface TSParseResult {
  entities: CodeEntity[]
  calls: CallEdge[]
  routes: RouteInfo[]
}

export function parseTypeScriptProject(rootDir: string, filePaths: string[]): TSParseResult { ... }
```

Implementation details for `parseTypeScriptProject`:

1. Create a TS program: `ts.createProgram(filePaths, { target: ES2022, module: ESNext, allowJs: true, noEmit: true, skipLibCheck: true, baseUrl: rootDir })`
2. Get the type checker: `program.getTypeChecker()`
3. Walk each source file (skip `.d.ts` files and anything in `node_modules`):
   - **Function declarations:** Extract name, parameters, return type, line numbers → `CodeEntity` with kind='function'
   - **Class declarations:** Extract name, methods → `CodeEntity` with kind='class', plus child entities for methods
   - **Method declarations:** Extract name, decorators → `CodeEntity` with kind='method', set `parentId` to class entity id
   - **Decorators:** Check for Express/NestJS patterns:
     - `@Controller('path')` → mark class as kind='controller'
     - `@Get('path')`, `@Post('path')`, etc. → create `RouteInfo` entries
     - Express-style: `router.get('/path', handler)` → `RouteInfo`
   - **Call expressions:** For each call, resolve the symbol via `checker.getSymbolAtLocation()`, create a `CallEdge` with the caller context
4. Process files in batches of 50 with `setImmediate()` between batches to avoid blocking main process
5. Return `{ entities, calls, routes }`

IMPORTANT: When walking the AST, track the current function/method context to properly assign `callerId` to CallEdge entries. Use a stack-based visitor:

```typescript
function createVisitor(sourceFile: ts.SourceFile, checker: ts.TypeChecker) {
  const contextStack: string[] = []  // stack of entity IDs

  function visit(node: ts.Node): void {
    // Push context for functions/methods
    if (ts.isFunctionDeclaration(node) || ts.isMethodDeclaration(node)) {
      const entityId = buildEntityId(sourceFile, node)
      contextStack.push(entityId)
      ts.forEachChild(node, visit)
      contextStack.pop()
      return
    }

    ts.forEachChild(node, visit)
  }

  return visit
}
```

**java-parser.ts** — Regex-based extraction for Spring Boot:

```typescript
export interface JavaParseResult {
  entities: CodeEntity[]
  routes: RouteInfo[]
}

export function parseJavaFile(content: string, filePath: string): JavaParseResult { ... }
export function parseJavaFiles(files: { path: string; content: string }[]): JavaParseResult { ... }
```

Regex patterns to implement:
- `@RestController` / `@Controller` — marks the class as a controller
- `@RequestMapping("basePath")` on class — extracts base path
- `@GetMapping("path")`, `@PostMapping("path")`, `@PutMapping("path")`, `@DeleteMapping("path")`, `@PatchMapping("path")` — extracts method + path
- `@Service` — marks as service entity
- `@Repository` — marks as repository entity
- `@Autowired` or constructor injection — creates CallEdge (inject type)
- Class declarations: `public class ClassName` → CodeEntity
- Method declarations: `public ReturnType methodName(params)` → CodeEntity

Strip single-line comments (`// ...`) and multi-line comments (`/* ... */`) BEFORE running regex patterns to avoid false positives from commented-out code.

For each controller class, combine base `@RequestMapping` path with method-level paths to produce `RouteInfo.fullPath`.

Regex patterns:

- Class defs: `class ClassName:` → CodeEntity with kind='class'
- Decorators: Capture all `@decorator_name` for entity.decorators array

Strip `#` comments before pattern matching.

**fe-parser.ts** — React component tree and routing extraction using TS Compiler API:

```typescript
import type { ComponentInfo } from '../../renderer/src/types/codebase-analyzer'

  components: ComponentInfo[]
  routes: { path: string; component: string }[]
}

export function parseFrontendProject(rootDir: string, filePaths: string[]): FEParseResult { ... }
```

Implementation:
1. Filter `filePaths` for `.tsx`, `.jsx`, `.ts`, `.js` files
2. Find entry point: look for `App.tsx` → `App.jsx` → `App.ts` → `App.js` → `index.tsx`
3. For each component file, use TS Compiler API to extract:
   - Default export function/const → component name
   - JSX elements with capital first letter → children (rendered components)
   - Import statements → imports list
   - `useState`, `useEffect`, `useCallback` etc. → hooks
   - Props parameter type/destructuring → props list
4. For routing detection, look for:
   - `<Route path="/..." element={<Component/>}>` — React Router v6
   - `<Route path="/..." component={Component}>` — React Router v5
   - File-based routing patterns (Next.js pages/ or app/ directory)
5. Build the component tree by matching children names to other discovered components

Implementation:
1. **Airflow DAGs:** Look for files in `dags/` directory or files containing `from airflow`:
   - `DAG('dag_id', ...)` or `@dag` decorator → PipelineInfo
   - `task_id = PythonOperator(task_id='name', ...)` → PipelineTask
   - `task1 >> task2` dependency chains → PipelineInfo.dependencies
   - `schedule_interval = '...'` → PipelineInfo.schedule
2. **dbt models:** If `dbt_project.yml` exists:
   - Each `.sql` file in `models/` → PipelineInfo with type='dbt-model'
   - `{{ ref('model_name') }}` references → dependencies
   - `{{ source('schema', 'table') }}` → mark as source
3. **Trigger scripts:** Look for files matching patterns:
   - `*_trigger.py`, `*_script.py`, `trigger_*.py`, `run_*.sh`
   - Shell scripts with cron-like headers or scheduling markers
   - Python scripts with `schedule` or `APScheduler` imports
4. Create CodeEntity for each function/class in DE files with appropriate kinds ('dag', 'task')

**parser/index.ts** — Parser orchestrator:

```typescript
import type { RepoType, AnalysisResult, CodeEntity, CallEdge, RouteInfo, ComponentInfo, PipelineInfo } from '../../renderer/src/types/codebase-analyzer'

export interface ParseResult {
  entities: CodeEntity[]
  calls: CallEdge[]
  routes: RouteInfo[]
  components: ComponentInfo[]
  pipelines: PipelineInfo[]
}

export async function parseRepository(
  repoPath: string,
  repoType: RepoType,
  framework: string,
  language: string,
  filePaths: string[],
  onProgress?: (filesProcessed: number, totalFiles: number) => void
): Promise<ParseResult> { ... }
```

Logic:
1. Filter out excluded paths: `node_modules/`, `.git/`, `dist/`, `build/`, `out/`, `.next/`, `__pycache__/`, `*.min.js`, `*.map`
2. Based on `repoType` and `language`:
   - `'backend'` + `'typescript'`/`'javascript'` → run `parseTypeScriptProject()`
   - `'backend'` + `'java'` → read Java files, run `parseJavaFiles()`
   - `'backend'` + `'python'` → read Python files, run `parsePythonFiles()`
   - `'frontend'` → run `parseFrontendProject()`
   - `'data-engineering'` → read relevant files, run `parseDEProject()`
   - `'fullstack'` → run both BE and FE parsers, merge results
3. Build the call graph from all entities + calls
4. Process files in batches, calling `onProgress` after each batch

**Complete `src/main/codebase-analyzer/analyzer.ts`** — Fill in the stub from Plan 01:

```typescript
async analyzeRepository(repoPath, branch, repoUrl, onProgress): Promise<AnalysisResult> {
  // 1. Get commit SHA
  const commitSha = await this.git.getCurrentCommit(repoPath)

  // 2. Check cache
  onProgress?.({ phase: 'scanning', progress: 0, detail: 'Checking cache...', filesProcessed: 0, totalFiles: 0 })
  const cached = this.cache.getAnalysis(repoUrl, branch, commitSha)
  if (cached) return cached

  // 3. Get file list
  onProgress?.({ phase: 'scanning', progress: 10, detail: 'Scanning files...', filesProcessed: 0, totalFiles: 0 })
  const filePaths = await this.git.getFileTree(repoPath)

  // 4. Detect repo type
  const classification = await detectRepoType(repoPath, filePaths)
  onProgress?.({ phase: 'scanning', progress: 20, detail: `Detected: ${classification.framework} (${classification.type})`, filesProcessed: 0, totalFiles: filePaths.length })

  // 5. Parse
  onProgress?.({ phase: 'parsing', progress: 25, detail: 'Parsing source files...', filesProcessed: 0, totalFiles: filePaths.length })
  const parseResult = await parseRepository(
    repoPath, classification.type, classification.framework, classification.language, filePaths,
    (processed, total) => {
      const pct = 25 + Math.round((processed / total) * 50)
      onProgress?.({ phase: 'parsing', progress: pct, detail: `Parsed ${processed}/${total} files`, filesProcessed: processed, totalFiles: total })
    }
  )

  // 6. Build file tree
  onProgress?.({ phase: 'indexing', progress: 80, detail: 'Building file tree...', filesProcessed: filePaths.length, totalFiles: filePaths.length })
  const fileTree = this.buildFileTree(filePaths)

  // 7. Compute stats
  const stats = this.computeStats(parseResult, filePaths)

  // 8. Assemble result
  const result: AnalysisResult = {
    repoId: '', // set by caller
    repoType: classification.type,
    framework: classification.framework,
    language: classification.language,
    commitSha,
    entities: parseResult.entities,
    calls: parseResult.calls,
    routes: parseResult.routes,
    components: parseResult.components,
    pipelines: parseResult.pipelines,
    fileTree,
    stats,
    documentation: '', // Will be generated by AI in Plan 06
  }

  // 9. Cache
  onProgress?.({ phase: 'indexing', progress: 90, detail: 'Caching results...', filesProcessed: filePaths.length, totalFiles: filePaths.length })
  this.cache.saveAnalysis(repoUrl, branch, commitSha, result)

  // 10. Index files for FTS
  await this.indexFilesForSearch(repoPath, repoUrl, filePaths)

  onProgress?.({ phase: 'done', progress: 100, detail: 'Analysis complete', filesProcessed: filePaths.length, totalFiles: filePaths.length })
  return result
}
```

Add `computeStats` method that counts files by language, entities by kind, total lines, route count, component count, pipeline count.

Add `indexFilesForSearch` method that reads file contents in batches and inserts into the FTS5 `file_index` and `file_index_fts` tables in the cache DB. Limit to source files only (not binary, not node_modules). Cap at 5000 files to avoid excessive indexing time.
