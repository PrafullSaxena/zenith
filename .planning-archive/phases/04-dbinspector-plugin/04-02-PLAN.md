2. **Create SqlEditor.tsx** — a React wrapper around CodeMirror 6:
   - Props: `{ value: string, onChange: (sql: string) => void, onExecuteCurrent: (sql: string) => void, onExecuteAll: () => void, schema: Record<string, string[]>, dialect: 'postgresql' | 'mysql', readOnly?: boolean, errorLine?: number, onEditorReady?: (view: EditorView) => void }`
   - Note: `onExecuteCurrent` now receives the SQL string to execute (either the selection or the statement at cursor).
   - Use `useRef<HTMLDivElement>` for container, `useRef<EditorView>` for editor instance
   - Create EditorView once in `useEffect` (mount only), store in ref. Do NOT recreate on every render — this is imperative, not controlled (see Research pitfall 2).
   - Extensions array:
     - `basicSetup` from `@codemirror/basic-setup` (line numbers, fold, search, brackets)
     - `oneDark` theme from `@codemirror/theme-one-dark`
     - `sql({ dialect: PostgreSQL or MySQL based on prop, schema, upperCaseKeywords: false })` from `@codemirror/lang-sql`
     - **Selection-aware execution keymap (Mod-Enter):** `{ key: 'Mod-Enter', run: (view) => { const state = view.state; if (!state.selection.main.empty) { const selectedSql = state.sliceDoc(state.selection.main.from, state.selection.main.to); onExecuteCurrent(selectedSql); } else { const { sql } = getStatementAtCursor(state); onExecuteCurrent(sql); } return true; } }` — Per user decision: "Highlight text to run selection; Ctrl+Enter runs current statement at cursor."
     - `{ key: 'Mod-Shift-Enter', run: () => { onExecuteAll(); return true } }`
     - `EditorView.updateListener.of(update => { if (update.docChanged) onChange(update.state.doc.toString()) })`
     - Custom dark theme overrides to match the app's oklch color scheme (bg-surface, text-text-primary colors): use `EditorView.theme({ '&': { backgroundColor: 'var(--color-surface)', color: 'var(--color-text-primary)' }, '.cm-gutters': { backgroundColor: 'var(--color-background)', borderRight: '1px solid var(--color-border)' } })`
   - When `schema` prop changes, reconfigure the sql extension dynamically using `view.dispatch({ effects: sqlCompartment.reconfigure(sql({ dialect, schema })) })`. Use `Compartment` from `@codemirror/state` for this.
   - When `errorLine` prop changes, add a line decoration (red background) on that line number using `Decoration.line` and a state field. Clear previous error decoration when errorLine is null.
   - SQL format on paste: intercept paste via `EditorView.domEventHandlers({ paste: ... })`, format with `sql-formatter` using the correct dialect, dispatch formatted text. Use try/catch since partial SQL may fail to format.
   - Format button handler: expose a `format()` method or accept an `onFormat` callback — format the entire document content via `sql-formatter`, dispatch replacement.
   - **Cursor-aware statement detection:** To support "run current statement at cursor" (Ctrl+Enter when no selection), implement a helper `getStatementAtCursor(state: EditorState): { from: number, to: number, sql: string }` that finds the semicolon-delimited statement containing the cursor position. Split on `;` considering string literals and comments (simple approach: split on `;` outside of single-quoted strings).
   - Expose `insertAtCursor(text: string)` method via `useImperativeHandle` or via the `onEditorReady` callback providing the EditorView — the schema browser will call this to insert table/column names. After insert, call `view.focus()` (see Research pitfall 7).
   - Cleanup: destroy EditorView on unmount via `view.destroy()` in useEffect cleanup.

1. **Extend db-store.ts** with query tab state and actions:
   - Add to state interface:
     - `queryTabs: QueryTab[]` (initialized to [])
     - `activeQueryTabId: string | null`
     - `savedQueries: SavedQuery[]` (initialized to [])
     - `columnsCache: Record<string, Record<string, { name: string, dataType: string }[]>>` — keyed by `connectionId:schema`, value is `tableName -> columns[]`. Used for CodeMirror autocomplete schema.
     - `isLoadingAllColumns: boolean`
   - Add a **`buildCmSchema` selector/helper** (either as a store getter or an exported function): transforms `columnsCache[connectionId:schema]` from `Record<string, { name: string, dataType: string }[]>` into the `Record<string, string[]>` format that CodeMirror's `sql()` extension expects — i.e., `{ tableName: [col1, col2, ...], ... }`. Map each table's column objects to just their `name` strings. This is called by QueryTab to derive the `schema` prop passed to SqlEditor. Example: `const buildCmSchema = (cache: Record<string, {name: string, dataType: string}[]>): Record<string, string[]> => Object.fromEntries(Object.entries(cache).map(([table, cols]) => [table, cols.map(c => c.name)]))`
   - Add actions:
     - `loadQueryTabs(connectionId: string)`: load tabs from `settings.get('queryConsole.tabs.${connectionId}')`, set `queryTabs` and `activeQueryTabId` to first tab (or create default tab if none saved)
     - `saveQueryTabs()`: persist current `queryTabs` to `settings.set('queryConsole.tabs.${activeConnectionId}', tabs)` — called after every mutation
     - `addQueryTab()`: create new `QueryTab` with `id: crypto.randomUUID()`, label `'Query ${queryTabs.length + 1}'`, empty sql, writeEnabled false, outputMode 'split', null lastResult. Add to `queryTabs`, set as active. Call `saveQueryTabs()`.
     - `closeQueryTab(tabId: string)`: remove from array, if closing active tab switch to the nearest tab. If last tab, create a fresh default one. Call `saveQueryTabs()`.
     - `setActiveQueryTab(tabId: string)`: update `activeQueryTabId`
     - `updateQueryTabSql(tabId: string, sql: string)`: update the tab's sql field. Debounce `saveQueryTabs()` call by 1 second.
     - `toggleWriteMode(tabId: string)`: flip `writeEnabled` on the tab. Call `saveQueryTabs()`.
     - `toggleOutputMode(tabId: string)`: flip `outputMode` between 'split' and 'inline' on the tab. Call `saveQueryTabs()`. Per user decision: "Toggle to switch to inline output mode (DataGrip-style)."
     - `renameQueryTab(tabId: string, label: string)`: update tab label. Call `saveQueryTabs()`.
     - `executeQuery(tabId: string, sql: string)`:
       - Find the tab, set its `lastResult` to `{ status: 'running', rows: [], fields: [], rowCount: 0, affectedRows: 0, executionTimeMs: 0, hasMore: false, sql, command: '' }`
       - Record `startTime = Date.now()`
       - Call `window.api.db.query(activeConnectionId, sql, tab.writeEnabled, 100, 0)` — pass limit=100, offset=0 for initial fetch
       - On success: update `lastResult` with rows, fields, rowCount, status 'success', executionTimeMs, command, hasMore (from IPC response).
       - On error: parse error message, try to extract line number (PostgreSQL returns `at line X`), set status 'error', error message, errorLine
       - Add to query history (type 'query' entry in history)
     - `loadMoreRows(tabId: string, offset: number)`: **Pagination action for "load more on scroll".** Find the tab's lastResult. Call `window.api.db.query(activeConnectionId, lastResult.sql, tab.writeEnabled, 100, offset)`. On success: **append** the new rows to `lastResult.rows` (do not replace), update `hasMore` from response, update `rowCount` to `lastResult.rows.length`. This is triggered by the ResultsGrid's scroll-to-end event.
     - `cancelQuery(tabId: string)`: call `window.api.db.cancelQuery(activeConnectionId)`, update tab's lastResult status to 'cancelled'
     - `loadAllColumnsForAutocomplete()`: call `window.api.db.allColumns(activeConnectionId, activeSchema)`, store in `columnsCache[connectionId:schema]`, set `isLoadingAllColumns` to false
     - `loadSavedQueries()`: load from `settings.get('dbInspector.savedQueries')`
     - `saveQuery(name: string, sql: string)`: add `SavedQuery` to `savedQueries`, persist via settings
     - `deleteSavedQuery(id: string)`: remove from array, persist
   - Call `loadQueryTabs(connectionId)` inside the existing `connectToDb` action (after successful connection) and inside `setActiveConnection` (when switching connections)
   - Call `loadAllColumnsForAutocomplete()` after schema is loaded (after tables load in the existing cascade)

   - Tab bar at top: renders each `QueryTab` as a closable tab button. Active tab has `border-b-2 border-accent` style (matching existing tab pattern). Each tab shows label + close (X) button. Double-click tab label to rename (inline input). "+" button to add new tab.
   - Below tab bar: renders `<QueryTab>` for the active tab

   - Reads query state from db-store: `queryTabs, activeQueryTabId, addQueryTab, closeQueryTab, setActiveQueryTab, renameQueryTab`

     - **Inline mode:** results render directly below each executed statement block within the editor area (DataGrip-style). In this mode, after execution, render the ResultsGrid (or placeholder for now) inline beneath the SQL text rather than in a separate bottom panel. Implement by rendering a scrollable container that interleaves SQL blocks and their result blocks vertically.
   - Top section: SqlEditor component with the tab's SQL content
   - **Build the CodeMirror schema prop:** call `buildCmSchema(columnsCache[connectionId:schema])` from db-store to transform the columnsCache into `Record<string, string[]>` format. Pass the result as the `schema` prop to SqlEditor.
   - Toolbar between editor and results:
     - Run button (play icon) — runs current statement (same as Ctrl+Enter)
     - Run All button (play-all icon) — runs all statements (same as Ctrl+Shift+Enter)
     - Cancel button (visible during execution only, square stop icon)
     - Write mode toggle: small switch/checkbox labeled "Write Mode" — toggles `writeEnabled`. When off, show lock icon. When on, show unlock icon with amber warning color.
     - **Output mode toggle:** button that switches between 'split' and 'inline' modes. Show `PanelBottom` icon for split mode, `AlignLeft` icon for inline mode. Tooltip: "Switch to inline/split output". Calls `toggleOutputMode(tabId)`. Per user decision: "Toggle to switch to inline output mode (DataGrip-style) — results appear inline after each statement."
     - Format button (code icon) — formats the editor content
     - Floating EXPLAIN icon: small button that sends current SQL to the existing Optimizer tab (call `setActiveTab('query-optimizer')` and `startOptimization(sql)`)
     - Connection status badge: green/red dot with connection name
   - Bottom section (split mode only): placeholder div for ResultsGrid (will be implemented in Plan 03). For now, render a simple `<pre>` showing JSON.stringify of `lastResult.rows` if available, or the error message.
   - Inline section (inline mode only): after execution, render result below the SQL statement as a compact inline block.
   - Status bar at very bottom: shows execution time (e.g. "1.23s"), row count (e.g. "100 rows"), affected rows for DML (e.g. "3 rows affected"), and query command (SELECT/INSERT/etc.)
   - Spinner with elapsed time counter: during execution (status === 'running'), show a spinner animation and a live-updating timer counting seconds since execution started (use `setInterval` with 100ms updates, display as "0.0s", "1.2s" etc.)
