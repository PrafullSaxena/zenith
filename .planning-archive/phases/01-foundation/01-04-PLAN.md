- Import `Store` from `electron-store` (ESM import — package.json has type=module)
- Create typed store with `new Store({ name: 'zenith-settings' })` — stores in OS app data directory
- Define default settings structure:
  ```ts
  const DEFAULTS = {
    general: {
      defaultView: 'code-review-bot',  // First plugin route
      showWelcomeOnStart: true,
    },
    plugins: {
      'code-review-bot': {},
      'db-inspector': {},
      'astro-patch': {},
      'prompt-builder': {},
    },
    agents: {},  // Reserved for 01-05
  }
  ```
- On first creation, seed store with DEFAULTS if empty
- Export functions:
  - `getSettings()` → returns entire store as object
  - `getSetting(key: string)` → dot-notation access (e.g., 'plugins.code-review-bot.workspace')
  - `setSetting(key: string, value: unknown)` → dot-notation write
  - `resetSettings(namespace: string)` → resets a namespace to its DEFAULTS subset (e.g., 'plugins.code-review-bot' resets that plugin's settings)

**ipc-handlers.ts** (`src/main/ipc-handlers.ts`):
- Import `ipcMain` from `electron`
- Import settings functions from `./settings-store`
- Import `safeStorage` from `electron` for credentials
- Register handlers:
  - `ipcMain.handle('settings:getAll', () => getSettings())`
  - `ipcMain.handle('settings:get', (_, key: string) => getSetting(key))`
  - `ipcMain.handle('settings:set', (_, key: string, value: unknown) => { setSetting(key, value) })`
  - `ipcMain.handle('settings:reset', (_, namespace: string) => { resetSettings(namespace) })`
  - `ipcMain.handle('credentials:set', (_, service: string, value: string) => { ... })` — use `safeStorage.encryptString(value)` and store the encrypted buffer. Store in a separate electron-store instance (`zenith-credentials`) keyed by service name. Store as base64 string of the encrypted buffer.
  - `ipcMain.handle('credentials:has', (_, service: string) => { ... })` — check if service key exists in credentials store
  - `ipcMain.handle('app:probeOllama', async () => { ... })` — try fetching `http://localhost:11434/api/tags` with a 3-second timeout. Return `{ available: boolean, models: string[] }`. Wrap in try/catch — if fetch fails, return `{ available: false, models: [] }`.
- Export a `registerIpcHandlers()` function that registers all handlers

**index.ts** (`src/main/index.ts`):
- Import `registerIpcHandlers` from `./ipc-handlers`
- Call `registerIpcHandlers()` in the `app.whenReady().then()` block BEFORE `createWindow()`
- This ensures IPC handlers are ready before the renderer loads

Note: The preload bridge (src/preload/index.ts) already calls these exact channel names. This task provides the main-process backing implementation.

**Zustand store** (`src/renderer/src/stores/settings-store.ts`):
- Create zustand store using `create` from `zustand`:
  ```ts
  interface SettingsState {
    settings: Record<string, unknown>
    isLoading: boolean
    loadSettings: () => Promise<void>
    getSetting: (key: string) => unknown
    setSetting: (key: string, value: unknown) => Promise<void>
    resetSettings: (namespace: string) => Promise<void>
  }
  ```
- `loadSettings`: calls `window.api.settings.getAll()`, stores result in state
- `getSetting`: reads from local state (dot-notation path resolution via simple split/reduce)
- `setSetting`: calls `window.api.settings.set(key, value)` then updates local state optimistically. Debounce is NOT needed — each change triggers one IPC call which is fine for settings forms.
- `resetSettings`: calls `window.api.settings.reset(namespace)` then reloads all settings

**SettingsField** (`src/renderer/src/components/settings/SettingsField.tsx`):
