# Plan 14-02: Fix Flow Diagram Rendering

## Goal
Ensure Flow diagrams actually render for BE repos now that callEdges are properly wired (from Plan 14-01). Fix any remaining issues in flow-utils and FlowsTab.

## Root Cause Analysis

The `buildAPIFlowNodes` function in `flow-utils.ts` (line 161-165) builds a call adjacency map using `c.callerId`/`c.calleeId`. With Plan 14-01 fixing the parser CallEdge type, these fields will now be correctly populated. However, there are still potential issues:

1. **Handler matching**: `entities.find(e => e.name === route.handlerName && e.filePath === route.filePath)` — the `route.filePath` from the parser is a relative path but entity `filePath` might have a different prefix format.
2. **Fallback flow**: When `nodes.length === 0` (no routes matched), the fallback at line 264-284 adds entities of relevant kinds but uses `c.id` (which doesn't exist on the canonical CallEdge) for edge IDs.
3. **Empty state UX**: The "No API endpoints found" message appears even if entities exist — should show the entity fallback flow instead.

## Tasks

<task id="1">
**Fix fallback edge ID reference**

In `src/renderer/src/plugins/cortex/components/flow-utils.ts`, line ~275:
```typescript
// Current (broken):
id: `e-${c.id}`,
// Fix to:
id: `e-${c.callerId}-${c.calleeId}`,
```
This `c.id` doesn't exist on the CallEdge interface used in flow-utils (which comes from the renderer's `cortex.ts` types).
</task>

<task id="2">
**Fix handler entity matching**

In `buildAPIFlowNodes`, the handler lookup at line ~193-197:
```typescript
const handler = entities.find(
  (e) => e.name === route.handlerName && e.filePath === route.filePath
)
```

The `route.filePath` from parsers is relative (e.g., `src/main/java/com/example/Controller.java`) and entity `filePath` should match, but verify both are using the same format. If not, normalize both paths before comparison.

Also relax matching: if exact match fails, try matching just by `handlerName` within the same controller class (using `route.controllerName` and entity `parentId`).
</task>

<task id="3">
**Improve fallback when routes exist but handlers don't match**

Currently the fallback only triggers when `nodes.length === 0`. But if routes exist (so the empty state check passes) and NO handlers match, the user sees "No flow data available" with no explanation.

Add a secondary fallback: if routes exist but no handler entities matched, show all controller/service/repository entities anyway (same as the `nodes.length === 0` fallback) rather than an empty diagram.
</task>

<task id="4">
**Add edge type from CallEdge.type if available**

The renderer's `CallEdge` type in `cortex.ts` has an optional `type` field. If available, use it for the edge label:
```typescript
data: { label: c.type ?? 'calls', type: c.type ?? 'call', animated: true }
```

Check the `CallEdge` interface in `src/renderer/src/types/cortex.ts` — if `type` field is missing, add it as optional:
```typescript
type?: 'inject' | 'call' | 'spark-pipeline'
```
</task>
