   - Add query-specific optional fields to `DbHistoryEntry`: `executedSql?: string`, `executionTimeMs?: number`, `resultRowCount?: number`
   - Add `'query-console'` to the `DbInspectorTab` type union

2. **Create mysql.ts** (`src/main/db/mysql.ts`):
   - Install `mysql2` dependency: the executor should run `npm install mysql2`
   - Create `MySqlConnectionManager` class mirroring `PostgresConnectionManager` interface:
     - Private `pools: Map<string, mysql.Pool>` and `configs: Map<string, DbConnectionConfig>`
     - `connect(config)`: create mysql2 pool via `mysql.createPool({ host, port, user, password, database, waitForConnections: true, connectionLimit: 5, connectTimeout: 15000 })`; verify with `SELECT 1`; if `readStrategy === 'read-only'`, set session `SET SESSION TRANSACTION READ ONLY` on each pool connection
     - `disconnect(connectionId)`: end pool
     - `testConnection(params)`: connect, run `SELECT VERSION() as version`, return version
     - `query(connectionId, sql, params?)`: execute via pool, return result mapped to `{ rows, fields: [{name, dataTypeID: 0}], rowCount, command }` matching PostgreSQL QueryResult shape
     - `getDatabases(connectionId)`: `SHOW DATABASES` filtering out information_schema, mysql, performance_schema, sys
     - `switchDatabase(connectionId, database)`: disconnect + reconnect with new database
     - `getSchemas(connectionId)`: MySQL doesn't have schemas like PG; return `[config.database]` (database name acts as schema)
     - `getTables(connectionId, schema)`: query `information_schema.TABLES WHERE TABLE_SCHEMA = ?` returning name, type, estimatedRows (TABLE_ROWS), totalSize (DATA_LENGTH + INDEX_LENGTH formatted)
     - `getColumns(connectionId, schema, table)`: query `information_schema.COLUMNS WHERE TABLE_SCHEMA = ? AND TABLE_NAME = ?` mapping to same column shape as PostgresConnectionManager
     - `getForeignKeys(connectionId, schema)`: query `information_schema.KEY_COLUMN_USAGE` joined with `TABLE_CONSTRAINTS` for foreign keys
     - `getIndexes(connectionId, schema, table)`: query `information_schema.STATISTICS`
     - `getTableStats(connectionId, schema, table)`: query `information_schema.TABLES` for row estimate, data/index sizes
     - `explain(connectionId, sql)`: run `EXPLAIN ${sql}` and return formatted text
   - Export `validateQuery` is already in postgres.ts — import and reuse it
   - Handle mysql2 error messages with the same enhanced error pattern (ETIMEDOUT, ENOTFOUND, ECONNREFUSED) as postgres.ts

3. **Create db-manager.ts** (`src/main/db/db-manager.ts`):
   - Import `PostgresConnectionManager` from `./postgres` and `MySqlConnectionManager` from `./mysql`
   - Create `UnifiedDbManager` class:
     - Private `pgManager = new PostgresConnectionManager()`
     - Private `mysqlManager = new MySqlConnectionManager()`
     - Private `engineMap = new Map<string, 'postgresql' | 'mysql'>()` — tracks which engine each connectionId uses
     - `connect(config: DbConnectionConfig)`: store `config.engine` in `engineMap`, delegate to appropriate manager
     - `disconnect(connectionId)`: delegate to correct manager based on `engineMap`, remove from map
     - `getManager(connectionId)`: return the correct manager based on `engineMap`
     - Forward all methods (`query`, `getDatabases`, `switchDatabase`, `getSchemas`, `getTables`, `getColumns`, `getForeignKeys`, `getIndexes`, `getTableStats`, `explain`, `testConnection`, `isConnected`, `getActiveConnections`, `disconnectAll`) by routing through `getManager(connectionId)` or for test which has no connectionId yet, accept an engine parameter
     - `cancelQuery(connectionId)`: for PostgreSQL, use `pg_cancel_backend` via a separate pool connection; for MySQL, use `KILL QUERY` via pool connection — store active query PIDs/thread IDs
