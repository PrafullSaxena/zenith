**Step 1: Create automated theme QA utility (src/renderer/src/lib/theme-qa.ts)**

Create a development-only utility that programmatically validates theme CSS variables:

```typescript
export interface ThemeQAResult {
  theme: string;
  passed: boolean;
  issues: ThemeIssue[];
}

export interface ThemeIssue {
  check: string;
  expected: string;
  actual: string;
  severity: 'error' | 'warning';
}
```

Implement `checkThemeContrast(themeName: string): ThemeQAResult` that:
- Reads CSS custom properties from `document.documentElement` via `getComputedStyle`
- Checks the following for each theme:
  1. **Text contrast**: `--color-text-primary` against `--color-bg-base` — compute relative luminance, verify WCAG AA ratio >= 4.5
  2. **Card visibility**: `--color-bg-card` differs from `--color-bg-base` by at least a small amount (cards must be visually distinct)
  3. **Accent visibility**: `--color-accent` has sufficient contrast against `--color-bg-card` (ratio >= 3.0 for large text/UI elements)
  4. **Status colors defined**: `--color-success`, `--color-error`, `--color-warning`, `--color-info` all resolve to non-empty values
  5. **Glow not overpowering**: `--color-accent-glow` opacity/alpha is <= 0.5 (if parseable)

Implement helper: `getRelativeLuminance(rgb: string): number` for WCAG luminance calculation.
Implement helper: `getContrastRatio(color1: string, color2: string): number`.

Also export `runFullThemeQA(themeNames: string[]): ThemeQAResult[]` that iterates all themes, applies each via the theme store's `setTheme`, waits a tick for CSS to apply, runs checks, and collects results.

**Step 2: Run automated QA across all 18 themes**

In a development context (or by temporarily adding a console call), run the automated checks against all 18 themes. Record which themes have issues.

**Step 3: Fix all found issues**

For each theme that fails automated checks:
- If text contrast is too low: adjust the theme's `--color-text-primary` or `--color-bg-base` in the theme definition file
- If card visibility is too low: adjust `--color-bg-card` to create more separation from `--color-bg-base`
- If accent contrast is too low: adjust `--color-accent` brightness
- If status colors are missing: add them to the theme definition
- If glow is overpowering: reduce alpha of `--color-accent-glow`

Also do a quick manual visual scan of each theme by reading the theme CSS variable definitions — look for obvious problems like:
- Very similar bg-base and bg-card (cards would be invisible)
- White text on light backgrounds or dark text on dark backgrounds
- Missing or undefined variables

Fix ALL issues found. The goal is zero known visual breakage across all 18 themes.

IMPORTANT: The theme-qa.ts utility is a development tool. It does not need to be imported in production code. It can be used from the browser console or a dev-only route.
