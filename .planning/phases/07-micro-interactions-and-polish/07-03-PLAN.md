First, identify all scrollable containers across the app:
```
grep -rn "overflow-y-auto\|overflow-auto\|overflow-y-scroll" src/renderer/src/ --include="*.tsx" | grep -v node_modules
```

For each scrollable panel that displays a list or content area (not tiny dropdowns or modals), wrap the existing scrollable div with `ScrollContainer` from `@renderer/components/ui`:

**Pattern:**
Before:
```tsx
<div className="overflow-y-auto flex-1 p-4 space-y-2">
  {items.map(...)}
</div>
```

After:
```tsx
<ScrollContainer className="flex-1 p-4 space-y-2">
  {items.map(...)}
</ScrollContainer>
```

ScrollContainer already provides `overflow-y: auto` internally, so remove any existing `overflow-y-auto` or `overflow-auto` class from the element being replaced.

**Priority targets** (scrollable list panels that benefit most from progress bar + shadows):
- QAPanel.tsx — chat message list
- APIListTab.tsx — API endpoint list
- RepoManager.tsx — repository list
- NoteList.tsx — note list sidebar
- DbHistory.tsx — query history list
- ReviewPanel.tsx — review findings list
- EstimationHistory.tsx — estimation history list
- HistoryPanel.tsx — TextCraft history list

**Skip** these (too small or have custom scroll behavior):
- GlassSelect dropdown (tiny, custom positioning)
- GlassModal body (modal has its own scroll container)
- GlassChat message area (if already handled internally)
- Any container that already manages scroll position programmatically (e.g., auto-scroll-to-bottom in chat)

For chat panels with auto-scroll-to-bottom behavior: use `showProgress={false}` since progress bars conflict with auto-scrolling chat UX. Keep `showShadows={true}` for visual depth.

IMPORTANT: Preserve all existing className values (flex-1, p-4, space-y-2, etc.) by passing them through ScrollContainer's className prop. Do not break existing layouts.
