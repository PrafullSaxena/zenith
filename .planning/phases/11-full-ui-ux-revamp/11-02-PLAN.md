**A. Contrast fixes across Dashboard, Activity, and About files:**

Open each file listed below and apply these opacity upgrades. The goal is to raise all low-opacity secondary text to meet WCAG AA (4.5:1 contrast ratio). The rule: never use `text-text-secondary` with opacity below `/60` for body text, or below `/50` for large text (18px+).

Replacements (apply across ALL files in this task):
- `text-text-secondary/30` -> `text-text-secondary/60`
- `text-text-secondary/40` -> `text-text-secondary/60`
- `text-text-secondary/50` -> `text-text-secondary/70` (for body-sized text; leave for large decorative text like hero icons where low contrast is intentional)

**EXCEPTION:** Do NOT change opacity on icon-only elements that are purely decorative (e.g., large background icons, divider lines). Only change text that users need to read.

Files to update:
1. **ActivityFeed.tsx** -- Raise `/30` and `/50` occurrences on text descriptions and empty state messages
2. **MissionControl.tsx** -- Raise any `/50` on section headers to `/70`
3. **HealthPanel.tsx** -- Raise low-contrast label text
4. **TokenChart.tsx** -- Raise low-contrast label text
5. **PluginCard.tsx** -- Raise low-contrast description text
6. **ActivityLog.tsx** -- Raise `/40` to `/60` and `/50` to `/70` on filter labels and entry descriptions
7. **AboutView.tsx** -- Raise `/50` to `/70` on capability descriptions and getting started text

**B. Semantic color migration in StatusBadge.tsx:**

Replace hardcoded Tailwind color classes with semantic tokens:
- `bg-green-500/10 text-green-400` -> `bg-success-muted text-success`
- `bg-red-500/10 text-red-400` -> `bg-error-muted text-error`
- `bg-yellow-500/10 text-yellow-400` (or `bg-amber-*`) -> `bg-warning-muted text-warning`
- `bg-blue-500/10 text-blue-400` -> `bg-info-muted text-info`
- `bg-gray-500/10 text-gray-400` -> keep as-is (gray is not semantic, it's neutral)

If StatusBadge uses a STATUS_STYLES or SEVERITY_CONFIG object mapping status strings to Tailwind classes, update the object values to use semantic tokens.

**C. Semantic diff colors in CodeReviewBot PRDiffView.tsx:**

Replace hardcoded diff colors with semantic tokens from Plan 01:
- `bg-green-950/30` (or similar green background for additions) -> `bg-diff-add`
- `bg-red-950/30` (or similar red background for deletions) -> `bg-diff-del`
- `text-green-400` (or similar green for `+` symbols) -> `text-diff-add-text`
- `text-red-400` (or similar red for `-` symbols) -> `text-diff-del-text`

Also fix any low-contrast text in PRDiffView (line numbers, file headers).

**D. CodeReviewBot PRList.tsx and ReviewHistory.tsx contrast:**

- PRList.tsx: Raise low-contrast text on PR descriptions, timestamps, branch names
- ReviewHistory.tsx: Migrate any hardcoded status colors to semantic tokens (success/error/warning). Raise low-contrast text on timestamps and metadata.
