  ```
  - Outer div: theme's bg color as backgroundColor, rounded-sm, overflow-hidden, relative
  - Inner div (glass surface): absolute, inset with small padding, rgba(255,255,255,0.03) bg, rgba(255,255,255,0.08) border, rounded-sm
  - Bottom accent line: absolute, bottom-0, small horizontal margins, 1px height, theme's accent color as backgroundColor
  ```
  Use inline styles for the theme-specific colors (bg, accent) since they come from metadata, not the active theme's CSS vars.

  **2. NEW Badge:**
  For theme cards in the 'new' section that are NOT the active theme, show a small GlassBadge with variant="accent" in the top-right corner displaying "NEW". When the theme IS active, show the existing check icon instead (don't show both).
  ```
  Import GlassBadge from '@renderer/components/ui'
  Condition: theme.section === 'new' && !isActive
  Position: absolute top-2 right-2
  Style: text-[10px] for compact size
  ```

  **3. Theme Crossfade Animation:**
  Add CSS transitions for smooth theme switching. The simplest reliable approach per research:
  - Add a style tag or modify existing global styles to include transitions on `html` and `body, #root` elements for `background-color` and `color` using `var(--duration-normal)` and `var(--ease-smooth)`.
  - If main.css is the better place for this (it is), add the transition rules there instead. But since 05-01 owns main.css, add the transition via a small inline style in App.tsx or via a className on the html element.
  - Simplest approach: Add the transition CSS rules to main.css at the end (coordinate with 05-01 — since both plans are wave 1, use the file ownership exception: 05-01 owns the theme blocks, 05-02 can append transition rules at the end of main.css after all theme blocks).

  Actually, to avoid file conflict with 05-01 which also modifies main.css, add the crossfade transition inline in GeneralSettings.tsx using a useEffect that sets `document.documentElement.style.transition` when the settings page mounts and cleans up on unmount. Or better: add it as a permanent style in App.tsx where the theme is applied.

  Best approach: In GeneralSettings.tsx, when the theme switch happens (the onClick handler), briefly add a CSS class to html that enables transitions, then remove it after the transition completes. This avoids transitions on initial page load. Use:
  ```
  document.documentElement.classList.add('theme-transitioning')
  setTimeout(() => document.documentElement.classList.remove('theme-transitioning'), 350)
  ```
  And add a style block (or CSS) for `.theme-transitioning, .theme-transitioning * { transition: background-color 300ms var(--ease-smooth), color 300ms var(--ease-smooth), border-color 300ms var(--ease-smooth); }`.

  Since we want this CSS rule to persist, add it as a `<style>` element via useEffect in GeneralSettings, or add it to main.css (acceptable since it's a single rule at the end, not a theme block).

  Final decision: Add the `.theme-transitioning` CSS rule to main.css (small, non-overlapping with theme blocks) and add the class toggle logic to the theme switch handler in GeneralSettings.tsx.
