  <name>Task 1: Automated cross-theme QA validation</name>
  <files>src/renderer/src/assets/main.css</files>
  <action>
  Perform automated QA across all 18 themes by examining the CSS values:

  1. **Glass surface visibility check:** For each theme, verify that --color-background lightness is between 10-16%. Glass surfaces use white-based transparency (oklch(100% 0 0 / 0.03)), which requires sufficiently dark backgrounds to be visible.

  2. **Accent contrast check:** For each theme, compute the lightness difference between --color-background and --color-accent. The gap should be at least 40% lightness units (e.g., bg at 12%, accent at 65% = 53% gap). Flag any theme where the gap is less than 40%.

  3. **Text contrast check:** For each theme, verify --color-text-primary lightness is >= 85% (ensuring strong contrast against dark backgrounds). Verify --color-text-secondary lightness is >= 50%.

  4. **Status color distinguishability check:** For each theme, verify that success (green hue ~142-150), error (red hue ~20-30), warning (amber hue ~75-85), and info (blue hue ~250-260) have distinct hues. Flag if any two status colors have hue difference < 30.

  5. **Glass-glow derivation check:** For each theme, verify --glass-glow uses the accent color at 0.2 opacity.

  If any issues are found, fix them directly in main.css by adjusting the problematic oklch values. Common fixes:
  - Background too light → reduce lightness to 10-12%
  - Accent too dim → increase lightness to 65-70%
  - Text too dark → increase lightness to 90%+
  - Status colors clashing → adjust hue or chroma

  Build the project to verify no CSS syntax errors: `npm run build`
