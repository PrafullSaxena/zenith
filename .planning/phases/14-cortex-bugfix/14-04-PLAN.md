# Plan 14-04: Fix Ask Section Agent Resolution

## Goal
Fix the Ask (Q&A) section to properly use the selected CLI agent and provide clear error handling when no agent is available.

## Root Cause Analysis

The `getCortexAgent()` function at `cortex-store.ts:189-201`:
```typescript
export function getCortexAgent() {
  const defaultAgentId = useSettingsStore.getState().getSetting('plugins.cortex.defaultAgent')
  const providers = useAgentStore.getState().providers
  const agent = defaultAgentId
    ? providers.find(p => p.id === defaultAgentId)
    : providers.find(p => p.status === 'connected' || p.hasApiKey)
  if (!agent) return null
  return { providerId: agent.id, model: agent.model ?? agent.id, command: agent.command }
}
```

**Issues identified:**
1. **Agent store may not be loaded**: `useAgentStore.getState().providers` may be empty if `loadProviders()` hasn't completed yet. The MissionControl component calls `loadProviders` on mount, but if the user navigates directly to Cortex, providers may not be loaded.
2. **CLI agent `command` field**: For CLI-based agents (like `claude`, `cursor`), the `command` field is what makes them work differently from API-based agents. If `command` is undefined, the IPC handler falls back to API streaming which may fail.
3. **Silent failure**: When `getCortexAgent()` returns null, `handleSend` returns early with no feedback. The `hasAgent` check disables the input, but the warning message is only shown in the empty state.
4. **Settings key mismatch**: The setting key `plugins.cortex.defaultAgent` was migrated from `plugins.cban.defaultAgent` — verify the migration works and the value is correctly read.

<task id="1">
**Ensure agent store is loaded before use**

In `QAPanel.tsx`, add an effect to load providers if they haven't been loaded yet:
```typescript
useEffect(() => {
  const store = useAgentStore.getState()
  if (store.providers.length === 0) {
    store.loadProviders()
  }
}, [])
```

Also do the same in `ArchitectureDashboard.tsx` for the `generateInsights` flow.
</task>

<task id="2">
**Add visible error state when no agent is available**

When `getCortexAgent()` returns null and the user tries to send a message:
- Show an inline error in the chat: "No AI agent available. Configure one in Settings → AI Agents."
- Make the error message a link to Settings

Currently `handleSend` just returns early silently. Add:
```typescript
if (!agent) {
  addQAMessage({
    id: crypto.randomUUID(),
    role: 'assistant',
    content: 'No AI agent is configured. Go to **Settings → AI Agents** to set one up.',
    sources: [],
    timestamp: new Date().toISOString()
  })
  return
}
```
</task>
