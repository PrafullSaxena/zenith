Types to export:
```typescript
export interface JiraCredentials {
  baseUrl: string      // e.g. "https://company.atlassian.net"
  email: string
  apiToken: string
  projects: string[]   // parsed from comma-separated CRED_JIRA_PROJECTS value
}

export interface JiraIssue {
  key: string
  summary: string
  status: string
  url: string
  description: string | null  // first 500 chars of description text
  assignee: string | null
  priority: string | null
}

export interface JiraSearchResponse {
  results: JiraIssue[]
  skipped: boolean
  reason: 'no_credentials' | 'error' | null
}
```

Main function to export:
```typescript
export async function searchJira(
  query: string,
  credentials: JiraCredentials | null
): Promise<JiraSearchResponse>
```

Implementation logic:
1. If credentials is null → return { results: [], skipped: true, reason: 'no_credentials' }
2. Detect if `query` is a direct Jira key pattern: /^[A-Z][A-Z0-9]+-\d+$/
   - If match → call GET {baseUrl}/rest/api/3/issue/{key} directly
   - Map single issue to JiraIssue, return { results: [issue], skipped: false, reason: null }
3. Otherwise → build JQL:
   - If credentials.projects.length > 0: `project IN (${projects.join(', ')}) AND text ~ "${query}"`
   - If no projects: `text ~ "${query}"`
   - Call POST {baseUrl}/rest/api/3/issue/search with body { jql, maxResults: 5, fields: ['summary', 'status', 'description', 'assignee', 'priority'] }
4. Auth: Authorization: Basic base64(`${email}:${apiToken}`), Content-Type: application/json, Accept: application/json
5. Map each issue from API response fields:
   - key: issue.key
   - summary: issue.fields.summary
   - status: issue.fields.status.name
   - url: `${baseUrl}/browse/${issue.key}`
   - description: extract plain text from issue.fields.description (it's Atlassian Document Format — just grab .content recursively or take first text node up to 500 chars; a simple recursive text extractor is fine)
   - assignee: issue.fields.assignee?.displayName ?? null
   - priority: issue.fields.priority?.name ?? null
6. Wrap entire function body in try/catch → catch returns { results: [], skipped: true, reason: 'error' }
7. Use Node's built-in fetch (available in Electron's Node 18+). Do NOT import node-fetch.
8. Timeout: wrap fetch with AbortController, 10 second timeout, catch abort error as reason: 'error'

Main function to export:
```typescript
export async function searchConfluence(
  query: string,
  credentials: ConfluenceCredentials | null
): Promise<ConfluenceSearchResponse>
```

Implementation logic:
1. If credentials is null → return { results: [], skipped: true, reason: 'no_credentials' }
2. Use Confluence REST API v1 (not v2):
   - Endpoint: GET {baseUrl}/wiki/rest/api/content/search
   - Query params: cql=`title~"${query}" OR label~"${query}"`, expand=`space,body.storage`, limit=3
   - Auth: Authorization: Basic base64(`${email}:${apiToken}`), Accept: application/json
3. Map each result:
   - title: result.title
   - url: `${baseUrl}/wiki${result._links.webui}` (Confluence uses _links.webui for page path)
   - spaceName: result.space.name
   - bodyExcerpt: strip HTML tags from result.body.storage.value using a simple replace(/<[^>]+>/g, ' ').replace(/\s+/g, ' ').trim().slice(0, 500)
4. Wrap entire function body in try/catch → catch returns { results: [], skipped: true, reason: 'error' }
5. Use Node's built-in fetch. AbortController with 10-second timeout.
6. URL-encode the CQL query parameter.
