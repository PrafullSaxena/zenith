  <name>Task 1: Create CodeEditor component with CodeMirror 6</name>
  <files>src/renderer/src/components/shared/code-editor.tsx</files>
  <action>
Create `src/renderer/src/components/shared/code-editor.tsx`.

**Props interface:**
```ts
interface CodeEditorProps {
  value: string
  onChange?: (value: string) => void
  language: 'sql' | 'typescript' | 'javascript' | 'python' | 'java' | 'json' | 'css' | 'html' | 'markdown' | 'yaml'
  readOnly?: boolean
  dialect?: 'postgresql' | 'mysql'
  schemaCompletions?: { tables: string[]; columns: Record<string, string[]> }
  lineHighlight?: number[]
  onExecute?: (selection?: string) => void
  placeholder?: string
  maxHeight?: string
  showLineNumbers?: boolean  // default true
  className?: string
}
```

**Implementation:**

1. **useRef + useEffect pattern**: Create the CodeMirror EditorView in a `useEffect` that runs on mount. Store the `EditorView` in a ref. Clean up on unmount with `view.destroy()`.

2. **Language extensions**: Create a helper `getLanguageExtension(language, dialect?, schemaCompletions?)` that dynamically returns the appropriate extension:
   - `sql`: `import { sql, PostgreSQL, MySQL } from '@codemirror/lang-sql'` -- pass dialect and schema for completions: `sql({ dialect: PostgreSQL, schema: schemaCompletions?.columns })`
   - `typescript`/`javascript`: `import { javascript } from '@codemirror/lang-javascript'` -- use `javascript({ typescript: language === 'typescript' })`
   - `python`: `import { python } from '@codemirror/lang-python'`
   - `java`: `import { java } from '@codemirror/lang-java'`
   - `json`: `import { json } from '@codemirror/lang-json'`
   - `css`: `import { css } from '@codemirror/lang-css'`
   - `html`: `import { html } from '@codemirror/lang-html'`
   - `markdown`: `import { markdown } from '@codemirror/lang-markdown'`
   - `yaml`: Use `StreamLanguage` from `@codemirror/language` with a simple yaml mode, or just use markdown as fallback

3. **Theme**: Create a custom zenith dark theme using `EditorView.theme({...})`:
   - Background: `hsl(240 6% 8%)` (--card)
   - Foreground: `hsl(0 0% 95%)` (--foreground)
   - Selection: `hsl(263 70% 58% / 0.2)` (primary at 20%)
   - Cursor: `hsl(263 70% 58%)` (primary)
   - Line numbers: `hsl(240 5% 65%)` (--muted-foreground)
   - Active line: `hsl(240 4% 16% / 0.5)` (--secondary at 50%)
   - Gutters: `hsl(240 6% 8%)` (--card)
   - Also apply `oneDark` from `@codemirror/theme-one-dark` as base, then override with zenith colors

4. **Keymaps**: Import `defaultKeymap`, `historyKeymap` from `@codemirror/commands`. If `onExecute` provided, add custom keymap: `{ key: 'Mod-Enter', run: () => { onExecute(getSelection()); return true } }` where `getSelection` gets the current selection text or full document text.

5. **Read-only mode**: When `readOnly`, set `EditorState.readOnly.of(true)` and `EditorView.editable.of(false)`. Show a copy button overlay in the top-right corner using absolute positioning: `Button` with `Copy` icon (variant="ghost", size="icon-xs"). On click, copy `value` to clipboard via `navigator.clipboard.writeText()`.

6. **Line highlighting**: If `lineHighlight` array provided, create a `StateField` or decoration that adds `bg-destructive/10` background to specified line numbers.

7. **External value sync**: Use a `Compartment` for the document content. When `value` prop changes externally and differs from editor state, dispatch a transaction to replace the document. This prevents cursor jump issues.

8. **Placeholder**: Use `placeholder()` extension from `@codemirror/view`.

9. **Container styling**: Wrap in a `div` with `rounded-2xl border border-border overflow-hidden` and optional `maxHeight` with `overflow-y: auto`. If `showLineNumbers` is false, don't include `lineNumbers()` extension.

10. **onChange**: Use `EditorView.updateListener.of((update) => { if (update.docChanged) onChange?.(update.state.doc.toString()) })`.

**Export:** Named export `CodeEditor` and `CodeEditorProps` type.

  <files>src/renderer/src/components/shared/file-tree.tsx</files>
  <action>
Create `src/renderer/src/components/shared/file-tree.tsx`.

**Types:**
```ts
interface FileTreeNode {
  name: string
  type: 'file' | 'folder'
  children?: FileTreeNode[]
  path: string
  language?: string
  size?: number
}

interface FileTreeProps {
  nodes: FileTreeNode[]
  onSelect: (node: FileTreeNode) => void
  selectedPath?: string
  searchable?: boolean
  defaultExpanded?: string[]
  defaultCollapsed?: string[]
  virtualScroll?: boolean
  className?: string
}
```

**Implementation:**

1. **State**: `expandedPaths: Set<string>` initialized from `defaultExpanded` (expanded) minus `defaultCollapsed` (collapsed). `searchQuery: string` for filter.

2. **Search**: If `searchable`, render `SearchInput` (import from `@renderer/components/shared/search-input`) at top. Filter nodes recursively: a folder is shown if any descendant file matches the query. A file is shown if its `name` includes the query (case-insensitive). When searching, auto-expand all matching folders.

   IMPORTANT: SearchInput is created in Plan 03-02. If building in parallel, create a simple inline search input as fallback (Input with Search icon) and note in the code that it can be swapped to SearchInput import later. Use a try-catch dynamic import or just build the inline version.

   ACTUALLY -- to avoid cross-plan dependency, implement the search inline using the shadcn Input + Search icon directly. Do NOT import from shared/search-input. This keeps the plans fully independent. The inline search is simple enough (just an Input with icon, no debounce needed for tree filtering).

3. **Tree rendering**: Recursive `TreeNode` component:
   - Folders: Clickable row with `ChevronRight` icon (rotates 90deg when expanded via `motion.div` with `animate={{ rotate: isExpanded ? 90 : 0 }}`), `Folder`/`FolderOpen` icon from lucide-react, folder name. Click toggles expanded state.
   - Files: Clickable row with language icon (see below), file name. Click calls `onSelect(node)`.
   - Indentation: Each level indented by `pl-{depth * 4}` or `paddingLeft: depth * 16`.
   - Active file: `selectedPath === node.path` gets `bg-primary/18 text-foreground` styling.
   - Hover: `hover:bg-secondary/50 transition-colors`

4. **Language icons**: Map `node.language` (or infer from file extension) to lucide icons or simple colored spans:
   - `.ts`/`.tsx`: Blue `FileCode` icon
   - `.js`/`.jsx`: Yellow `FileCode` icon
   - `.py`: Green `FileCode` icon
   - `.json`: Orange `FileJson` icon
   - `.css`/`.html`: Pink `FileCode` icon
   - `.md`: Gray `FileText` icon
   - Default: `File` icon
   Use `cn()` to apply `text-blue-400`, `text-yellow-400`, etc. based on language.

5. **Expand/collapse animation**: Use `framer-motion` `AnimatePresence` + `motion.div` for folder children:
   ```tsx
   <AnimatePresence initial={false}>
     {isExpanded && (
       <motion.div
         initial={{ height: 0, opacity: 0 }}
         animate={{ height: 'auto', opacity: 1 }}
         exit={{ height: 0, opacity: 0 }}
         transition={{ duration: 0.15 }}
         style={{ overflow: 'hidden' }}
       >
         {children}
       </motion.div>
     )}
   </AnimatePresence>
   ```

6. **Keyboard navigation**: Add `onKeyDown` handler on the tree container:
   - `ArrowDown`: Move focus to next visible node
   - `ArrowUp`: Move focus to previous visible node
   - `ArrowRight`: Expand folder / move to first child
   - `ArrowLeft`: Collapse folder / move to parent
   - `Enter`: Select file or toggle folder
   Track `focusedPath` in state, use `tabIndex={0}` and `data-path` attributes for focus management.

7. **Virtual scroll**: When `virtualScroll` is true and flattened visible nodes > 500, use `@tanstack/react-virtual`. Flatten the visible tree into an array, virtualize it. When off, render normally.

8. **Tooltip**: On file hover, show `Tooltip` with file size and language if available.
