**Class structure:**

```typescript
export class PricingSync {
  private dailyTimer: NodeJS.Timeout | null = null
  private mainWindow: BrowserWindow | null = null

  // Call once during app startup. Attaches mainWindow for push notification.
  // Schedules daily sync: runs immediately if last sync was >23h ago, else
  // waits until 23h after last sync.
  init(mainWindow: BrowserWindow): void

  // Register the window for launchpad:syncComplete push events.
  // Called when mainWindow becomes available (may differ from init timing).
  setMainWindow(mainWindow: BrowserWindow): void

  // Run sync for all 3 providers. Results are isolated — one failure does
  // not abort others. Emits launchpad:syncComplete to renderer on completion.
  async syncAll(): Promise<SyncResult>

  // Sync a single provider. Delegates to the appropriate fetcher.
  // Writes result to pricing_sync_log via pricingRepository.logSync()
  async syncProvider(provider: 'aws' | 'gcp' | 'azure'): Promise<ProviderSyncResult>

  private scheduleNext(delayMs: number): void
  private clearSchedule(): void
}

export const pricingSync = new PricingSync()
```

**Implementation details:**

- `init()`: Reads last sync time from `pricingRepository.getSyncStatus('aws')` (use AWS as reference; all providers sync together). Calculates `msSinceLastSync`. If `msSinceLastSync > 23 * 60 * 60 * 1000` or no prior sync, calls `syncAll()` with a 10-second startup delay (setTimeout, not immediate). Then calls `scheduleNext(24 * 60 * 60 * 1000)`.
- `syncAll()`: Runs `syncProvider('aws')`, `syncProvider('azure')`, `syncProvider('gcp')` in parallel via `Promise.allSettled`. Collects results. Calls `mainWindow.webContents.send('launchpad:syncComplete', result)` if mainWindow is non-null. Returns `SyncResult`.
- `syncProvider()`: Wraps fetcher call in try/catch. On success: calls `pricingRepository.logSync(provider, 'success', servicesUpdated, null)`. On error: calls `pricingRepository.logSync(provider, 'error', 0, error.message)`. Returns `ProviderSyncResult` in both cases.
- Import `fetchAwsPricing` from `./fetchers/aws-fetcher` (will be created in Task 2). Import `fetchAzurePricing` from `./fetchers/azure-fetcher` and `fetchGcpPricing` from `./fetchers/gcp-fetcher` — these will be created in plan 08-02. For now, stub them as no-ops returning `{ servicesUpdated: 0, deltaSkipped: true }` directly in the `syncProvider` method if the import fails at compile time. Use dynamic `await import()` or guard with try/catch to allow 08-01 and 08-02 to compile independently.

**IMPORTANT — avoiding circular imports:** `pricing-sync.ts` must NOT be imported by `pricing-repository.ts` or `pricing-db.ts`. The dependency arrow is strictly: `pricing-sync` → `pricing-repository` → `pricing-db`.

**Delta check strategy:**
The bulk JSON has a top-level `publicationDate` field (ISO string). Store the last-seen value in a module-level variable or read it from `pricing_sync_log` (check `pricingRepository.getSyncStatus('aws')` — add a `lastPublicationDate` field to the sync log if needed, OR store in a simple JSON sidecar file at `app.getPath('userData')/pricing-aws-meta.json`). Use the sidecar file approach (simpler — no schema change):
- On fetch: read `pricing-aws-meta.json` for `{ publicationDate: string }`. If current bulk JSON `publicationDate` matches, return `{ servicesUpdated: 0, deltaSkipped: true, bytesDownloaded: headSize }`.
- On update: after upsert completes, write new `publicationDate` to the sidecar file.

**Parsing strategy:**
The bulk JSON is large. Instead of `JSON.parse` on the full body (OOM risk), use a streaming JSON parser. However, for an Electron desktop app where memory is less constrained, `JSON.parse` on the full buffer is acceptable if we limit scope. Download the full JSON, `JSON.parse`, then filter:

```
data.products → each product has attributes.location, productFamily="Compute Instance"
data.terms.OnDemand → price dimensions per SKU
```

Extract for each product where `attributes.location` is in our location set:
- `serviceId` = derive from service type — map to a canonical service id. For EC2, use `'ec2-on-demand'` as the service_id (matches what the seed catalog uses — check seed.ts to confirm the exact service id strings).
- `rate_key` = `'pricePerHour'`
- `value` = USD per hour from `priceDimensions[*].pricePerUnit.USD`
- `tier` = `'onDemand'`
- `region` = reverse-lookup from location to region code

Call `pricingRepository.upsertRates(rateRows)` in batches of 500 to avoid huge transactions.
