**Updated GroomingResult interface** — add two new fields:
```ts
export interface GroomingResult {
  priority: 'p1' | 'p2' | 'p3'
  priorityRationale: string
  suggestedAction: 'do' | 'delegate' | 'defer' | 'delete'
  summary: string | null           // NEW: source-by-source Summary section (replaces evidenceSummary)
  nextSteps: string | null          // NEW: 3-5 bullet Next Steps section
  evidenceSummary: string | null    // KEEP: set to same value as summary for backward compat with existing DB + store
  jiraTicketKey: string | null
  jiraTicketUrl: string | null
  researchSummary: string | null
  researchLinks: string | null
  groomedAt: number
  sourcesUsed: ('ai' | 'jira' | 'confluence' | 'google')[]   // NEW
}
```

**Stage callback parameter** — add optional onStage callback to groomTask signature:
```ts
export async function groomTask(
  task: Task,
  onStage?: (stage: 'analyzing' | 'querying' | 'summarizing') => void
): Promise<GroomingResult>
```
This lets the batch runner and re-groom handler emit stage-specific progress events. Callers that pass no onStage still work.

**Two-pass groomTask implementation:**

Pass 1 — Source selection prompt (compact TOON format):

```
SYSTEM: You are a task groomer. Respond with JSON only.

USER:
TASK: {task.text}

Decide which sources are needed to groom this task.
If the task is short and self-evident (typo fix, version bump, config change) — no sources needed.
If the task is ambiguous, technical, or multi-step — select the relevant sources.

Available sources: jira, confluence, google

Respond with exactly this JSON:
{
  "sourcesNeeded": ["jira", "confluence", "google"] | [],
  "skipReason": "short/clear task" | null,
  "summary": "<Source-by-source findings if no sources needed. Format: '## Summary\n[No external sources needed — task is self-evident.]\n\n## Next Steps\n- bullet1\n- bullet2 (3-5 bullets)'>",
  "nextSteps": null
}

Rules:
- If sourcesNeeded is empty: populate summary with a complete ## Summary and ## Next Steps section. nextSteps must be null (summary contains both).
- If sourcesNeeded is non-empty: set summary=null and nextSteps=null (pass 2 will produce them).
- sourcesNeeded items: only include sources that would plausibly have relevant content for THIS specific task.
- 'google' is always available. 'jira'/'confluence' only when the task involves project work or existing docs.
```

Call AI with maxTokens: 512 (compact response). Emit onStage?.('analyzing').

After pass-1 response parse:
- If sourcesNeeded is empty → skip to result assembly with summary from pass-1, no pass-2
- If sourcesNeeded is non-empty → emit onStage?.('querying'), query only the selected sources in parallel

Pass 2 — Summarization prompt (only when sources were queried):

```
SYSTEM: You are a task groomer. Respond with JSON only.

USER:
TASK: {task.text}

SOURCE RESULTS:
{integrationContext — only lines for sources that returned results}

Produce structured grooming output. Respond with exactly this JSON:
{
  "priority": "p1" | "p2" | "p3",
  "priorityRationale": "<one sentence, e.g. P1 — blocks auth release>",
  "suggestedAction": "do" | "delegate" | "defer" | "delete",
  "jiraTicketKey": "<PROJ-42 if confident same work item, else null>",
  "jiraTicketUrl": "<full URL if jiraTicketKey set, else null>",
  "isResearchMode": true | false,
  "researchLinks": [{"title":"...","url":"..."}] | null,
  "summary": "## Summary\n[Source-by-source blocks, one per source with results. Omit sources with no results.]\n\n## Next Steps\n- bullet1\n- bullet2\n(3-5 bullets mixing open questions + concrete actions)",
  "nextSteps": null
}
```

Emit onStage?.('summarizing') before calling AI for pass-2. maxTokens: 1024.

**Result assembly:**
- sourcesUsed: always includes 'ai'; add 'jira'/'confluence'/'google' for each source that was queried AND returned non-empty results (not just attempted)
- summary: from pass-1 (no-sources path) or pass-2 (sources path)
- evidenceSummary: set to summary value (backward compat — existing DB column + store reads this field)
- nextSteps: null (embedded in summary string)
- priority/priorityRationale/suggestedAction: from pass-2 if sources path; for no-sources path, run a minimal AI assessment inline in pass-1 (add priority/priorityRationale/suggestedAction to the pass-1 JSON schema when sourcesNeeded is empty)
- researchSummary: null (replaced by structured summary field; keep in GroomingResult as null for backward compat)
- researchLinks: from pass-2 if isResearchMode=true

**Pass-1 extended schema for no-sources path** — when sourcesNeeded is empty, the pass-1 JSON also includes:
```json
{
  "sourcesNeeded": [],
  "priority": "p1" | "p2" | "p3",
  "priorityRationale": "...",
  "suggestedAction": "do" | "delegate" | "defer" | "delete",
  "summary": "## Summary\n...\n\n## Next Steps\n- ...",
  "nextSteps": null
}
```
This avoids a second AI call entirely for simple tasks.
