Add a DB catalog slice to the Zustand store. The existing `getCatalog()` (TS import) is still used by ResourceConfigurator for configSchema access — do NOT remove it.

**Types to add (in the store file or imported from launchpad types):**
```ts
interface DbService {
  id: string
  name: string
  category: string       // raw category string from DB (e.g. "Compute", "ML/AI")
  description: string | null
  equivalenceId: string | null
}
interface DbCatalogState {
  services: DbService[]           // flat list of all services for provider
  categories: string[]            // ordered unique category names
  searchIndex: string[]           // parallel array — lowercased "name category" for each service
  status: 'idle' | 'loading' | 'ready' | 'error'
}
```

**Store state additions:**
```ts
dbCatalog: DbCatalogState  // initialized as { services: [], categories: [], searchIndex: [], status: 'idle' }
```

**Store action additions:**
```ts
loadDbCatalog: (provider: CloudProvider) => Promise<void>
```

**loadDbCatalog implementation:**
1. Set `dbCatalog.status = 'loading'`
2. Call `window.api.launchpad.getCatalog(provider)` — the IPC handler returns `ServiceCategory[]` where each has `{ id, name, services: ServiceEntry[] }` (see pricing-repository.ts getCatalog return shape)
3. Flatten to a `DbService[]` sorted by category then name:
   ```ts
   const flat: DbService[] = categories.flatMap(cat =>
     cat.services.map(s => ({ id: s.id, name: s.name, category: cat.name, description: s.description, equivalenceId: s.equivalenceId }))
   )
   ```
4. Build `categories: string[]` — unique category names in order they appear
5. Build `searchIndex: string[]` — parallel to flat: `\`${s.name.toLowerCase()} ${s.category.toLowerCase()}\``
6. Set `dbCatalog = { services: flat, categories, searchIndex, status: 'ready' }`
7. On error: set `dbCatalog = { services: [], categories: [], searchIndex: [], status: 'error' }` — do not throw, do NOT fall back to TS catalog import

**Trigger loadDbCatalog:** Call it inside the existing `setProvider` action after updating `provider`. Also call it in `initStore` (or wherever the store initializes on mount — check if there's an init action; if not, ServiceCatalog will call it via useEffect).

The `getCurrentCatalog` selector still uses the TS import as before — do NOT change it. It's used by ResourceConfigurator for configSchema access which is not changing this phase.

IMPORTANT: The `window.api.launchpad.getCatalog` signature — check `src/renderer/src/types/electron.d.ts`. If `getCatalog` is not declared there (it was added to `preload/index.d.ts` in phase 08 but the renderer-side `electron.d.ts` was updated in phase 09-03) — add it:
```ts
getCatalog: (provider: string) => Promise<ServiceCategory[]>
```
where ServiceCategory here is the repository's return type. Use a local inline type or `any` if needed to avoid circular import — but prefer a typed declaration.

**Store selectors:**
```ts
const dbCatalog = useLaunchpadStore(s => s.dbCatalog)
const loadDbCatalog = useLaunchpadStore(s => s.loadDbCatalog)
const selectedServices = useLaunchpadStore(s => s.selectedServices)
const addService = useLaunchpadStore(s => s.addService)
```

**Load catalog on provider change:**
```ts
useEffect(() => {
  loadDbCatalog(provider)
  setSearchQuery('')
  setActiveCategory('All')
}, [provider, loadDbCatalog])
```

**Filtered items (derived, useMemo):**
```ts
const filteredItems = useMemo(() => {
  const { services, searchIndex } = dbCatalog
  let items = services

  if (searchQuery.trim()) {
    // Search overrides category chip — flat results
    const q = searchQuery.toLowerCase().trim()
    items = services.filter((_, i) => searchIndex[i]?.includes(q))
  } else if (activeCategory !== 'All') {
    items = services.filter(s => s.category === activeCategory)
  }
  return items
}, [dbCatalog, searchQuery, activeCategory])
```

**Virtualizer setup (row height = 40px):**
```ts
const rowVirtualizer = useVirtualizer({
  count: filteredItems.length,
  getScrollElement: () => parentRef.current,
  estimateSize: () => 40,
  overscan: 5,
})
```

**Loading state:** When `dbCatalog.status === 'loading'`, render 8 skeleton rows (h-10 each).

**Empty state:** When `filteredItems.length === 0` and searchQuery is set, render plain text: `No services match "{searchQuery}"` — no icon, no card, just a `<p className="text-xs text-muted-foreground/50 p-4">`.

**Filter chips:** Horizontal scrollable row:
```tsx
<div className="flex gap-1.5 overflow-x-auto pb-1 no-scrollbar">
  {['All', ...dbCatalog.categories].map(cat => (

      {cat}

  ))}
</div>
```

**Row render (inside virtualizer map):**
Each virtual item renders a `<button>` positioned absolutely via `translateY`. Row height: 40px.

```tsx
const virtualItems = rowVirtualizer.getVirtualItems()
```
