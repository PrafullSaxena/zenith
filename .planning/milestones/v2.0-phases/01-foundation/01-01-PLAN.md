  <name>Task 1: Install dependencies and configure shadcn CLI</name>
  <files>package.json, pnpm-lock.yaml, components.json, src/renderer/src/lib/utils.ts</files>
  <action>
1. Install runtime dependencies via pnpm:
   ```
   pnpm add clsx tailwind-merge class-variance-authority
   ```

2. Install Animate-UI:
   ```
   pnpm add animate-ui
   ```
   Note: shadcn is already in devDependencies (v4.1.0). tw-animate-css is already installed.

3. Create `components.json` in project root with this exact config (Tailwind CSS v4 style, no cssVariables flag needed since v4 uses @theme):
   ```json
   {
     "$schema": "https://ui.shadcn.com/schema.json",
     "style": "new-york",
     "rsc": false,
     "tsx": true,
     "tailwind": {
       "config": "",
       "css": "src/renderer/src/assets/main.css",
       "baseColor": "zinc",
       "cssVariables": true
     },
     "aliases": {
       "components": "@renderer/components",
       "ui": "@renderer/components/ui",
       "hooks": "@renderer/hooks",
       "lib": "@renderer/lib",
       "utils": "@renderer/lib/utils"
     },
     "iconLibrary": "lucide"
   }
   ```
   Key points:
   - `rsc: false` because this is an Electron app, not Next.js
   - Aliases use `@renderer/*` matching tsconfig.web.json paths
   - CSS path points to the actual main.css entry point
   - No tailwind.config path needed for Tailwind v4 (uses CSS-first config)

4. Create `src/renderer/src/lib/utils.ts`:
   ```typescript
   import { type ClassValue, clsx } from "clsx"
   import { twMerge } from "tailwind-merge"

   export function cn(...inputs: ClassValue[]) {
     return twMerge(clsx(inputs))
   }
   ```

5. Verify the existing `@renderer` alias works in `electron.vite.config.ts` (it does -- `resolve.alias` maps `@renderer` to `src/renderer/src`). Confirm `tsconfig.web.json` has `@renderer/*` path (it does). No changes needed to either config.
  </action>
